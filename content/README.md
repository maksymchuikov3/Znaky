# Контент: формат пакета питань

Застосунок працює офлайн: питання поставляються у файлі
`core/data/src/main/assets/content/questions.json` і при першому запуску (або коли
`version` у файлі більша за збережену) завантажуються в локальну базу Room.
Прогрес користувача при оновленні контенту зберігається.

> ⚠️ Зараз у файлі — **26 зразкових питань, написаних нами** для розробки й тестів.
> Це не офіційна база. Перед релізом їх потрібно замінити на імпорт з відкритої бази ГСЦ МВС
> і звірити кожне посилання на пункт ПДР з чинною редакцією (zakon.rada.gov.ua).

## Схема

```jsonc
{
  "version": 1,                       // збільшувати при кожній зміні
  "rulesEdition": "…",                // редакція ПДР, показується користувачу
  "topics": [
    { "id": "tr-12", "number": "12", "title": "Швидкість руху", "block": "TRAFFIC_RULES" }
  ],
  "questions": [
    {
      "id": "q-0001",                 // стабільний; на нього посилається прогрес
      "topicId": "tr-12",
      "text": "…",
      "answers": [ { "id": "a", "text": "…" }, { "id": "b", "text": "…" } ],
      "correctAnswerId": "b",
      "image": "art:sign:3.29",       // необов'язково: шлях в assets або намальована ілюстрація (див. нижче)
      "ruleRefs": ["12.4"],           // пункти ПДР
      "explanation": "…",             // наше власне пояснення, необов'язково
      "categories": ["B", "BE"]       // категорії посвідчення
    }
  ]
}
```

`image` — або шлях до картинки в assets, або намальована ілюстрація з `core:art`:
`art:sign:<код знака>` (наприклад `art:sign:2.3`), `art:scene:crossroads`, `art:scene:crossroads-light`,
`art:scene:officer`.

`rules` (на верхньому рівні, поруч із `topics`) — словник «пункт ПДР → текст пункту». Під поясненням
питання показується цитата кожного пункту з `ruleRefs`. Якщо словник не порожній, валідатор вимагає,
щоб кожен `ruleRefs` у ньому був. Текст пунктів — переказ офіційної редакції ПДР.

`block` — один з: `TRAFFIC_RULES` (ПДР), `ROAD_SAFETY` (безпека руху), `VEHICLE` (будова ТЗ),
`FIRST_AID` (домедична допомога). Від блоку залежить розподіл 10/4/4/2 в іспиті.

## Правила

- Питання й ілюстрації — тільки з офіційних відкритих джерел. Тексти пояснень пишемо самі;
  не копіюємо пояснення, картинки чи формулювання з інших застосунків і сайтів.
- `id` питань не змінюються між версіями, інакше користувачі втратять прогрес.
- Валідатор (`ContentPackValidator`) запускається в юніт-тесті `BundledContentTest` у CI:
  дублікати, невідомі теми/категорії, відсутня правильна відповідь ламають збірку.

## Мото (A, A1) і судноводій (BOAT)

Окремі курси зберігаються в тому ж пакеті. Аудиторію теми визначає префікс її `id`:

| Префікс | Для кого | Звідки |
| --- | --- | --- |
| `mo-` | категорії A і A1 (разом із загальними питаннями ПДР) | `tools/content/moto_questions.py` — питання наші, за офіційним текстом ПДР |
| `bt-` | лише категорія `BOAT` (дорожні теми їй не показуються) | `tools/content/boat_questions.py` — питання наші, за Законом «Про внутрішній водний транспорт» і Правилами плавання |

Після зміни цих файлів запустіть з кореня репозиторію:

```
python3 tools/content/build_pack.py   # оновлює questions.json (теми й питання mo-/bt-)
python3 tools/content/courses.py      # тексти курсів: feature/car/src/main/assets/courses/{moto,boat}.json
python3 tools/content/anatomy_parts.py  # 3D-частини мотоцикла і катера (запускати на parts.json з main)
```

Посилання `ruleRefs` для мото — пункти ПДР з підпунктом (`2.3 «г»`), для човнів — назва документа і розділу
(`Правила плавання: рятувальні засоби`). Кожне посилання має бути в мапі `rules`, інакше валідатор не пропустить пакет.
Офіційної відкритої бази питань для малих суден немає; офіційні питання ГСЦ для A/A1 є лише в PDF-скані на hsc.gov.ua.
